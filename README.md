# Creative MCP — развёртывание инструментов для фото и видео

Локальная среда **Codex CLI + MCP + GIMP 3 + Blender** для создания изображений,
графических заставок, титров и анимации. Репозиторий называется
`mcp_for_photos_videos`, Python-пакет и MCP-сервер — `creative-mcp`.

Заставка Peppers.group — первый пример применения, а не ограничение проекта.

## Что готово

- Единый Python-установщик с оболочками для Linux/macOS и Windows.
- Отдельное `.venv`, установка базового MCP, обнаружение приложений и конфигурация.
- Опциональная установка отсутствующих GIMP 3, Blender и Codex.
- Подключение к Codex по STDIO без открытых портов и постоянно работающего сервиса.
- Сохранение существующих настроек, режим `--dry-run`, краткая проверка `--doctor`.
- MCP-инструмент **`system_info`**: версии реально настроенных GIMP и Blender.

**Граница версии 0.2:** репозиторий развёртывает базовую среду. Инструменты
редактирования слоёв, создания сцен и рендера ещё не включены. Разрабатываемый
на AAF-Note GIMP-адаптер нужно перенести отдельным изменением после проверки его
исходников. Установщик не копирует несуществующий код с ноутбука и не обещает
генерацию лиц средствами одного MCP.

## Поддерживаемые системы

«На любом компьютере» здесь означает переносимость на поддерживаемые ОС,
а не гарантию для любого оборудования, дистрибутива или архитектуры.

| Система | Установка приложений | Статус |
|---|---|---|
| Astra / Debian / Ubuntu | apt устанавливает Flatpak при необходимости; GIMP 3 и отсутствующий Blender — пользовательские Flatpak | Компоненты проверены пользователем на Astra 1.8.7 x86_64; новый установщик целиком ещё не запускался на ноутбуке |
| Fedora / Arch / openSUSE | dnf / pacman / zypper для Flatpak, далее Flathub | Реализовано; требуется проверка на машине |
| Другой Linux | Заранее установленный Flatpak либо ручная установка приложений | Реализовано обнаружение; требуется проверка |
| macOS | Существующий Homebrew: `brew install --cask` | Реализовано; требуется проверка |
| Windows | Существующий winget; native Python | Реализовано; требуется проверка |

Архитектуры зависят от доступности пакетов GIMP, Blender, Codex и Python-зависимостей.
WSL не заменяет native Windows-установку: у него отдельные пути, настройки и окружение;
работа графических приложений требует отдельной настройки и здесь не проверялась.

## Требования

- Python **3.11+**, работающие `venv` и pip; Git для клонирования.
- Интернет для загрузки пакетов и входа в Codex.
- GIMP **3+**, Blender **3+**: можно установить заранее или флагом `--install-apps`.
- На Linux — графический сеанс и поддержка Flatpak, если выбран этот вариант.
- На macOS — Homebrew для автоматической установки приложений.
- На Windows — winget; для `--install-codex` нужен Node.js LTS с npm.

Сам установщик запускайте **обычным пользователем**. Только установка отсутствующего
Flatpak через системный пакетный менеджер запросит `sudo`; Windows-пакеты могут
показать UAC. Системный Python и старый GIMP не удаляются.

Для Astra/Debian/Ubuntu при отсутствии базовых компонентов:

```bash
sudo apt update && sudo apt install python3 python3-venv git
```

Если репозиторий дистрибутива поставляет Python ниже 3.11, установите подходящий
пользовательский Python отдельно; не заменяйте системный интерпретатор.

## Быстрый старт: Linux и macOS

```bash
git clone https://github.com/AlekseyAnoshko/mcp_for_photos_videos.git
cd mcp_for_photos_videos
sh install.sh --install-apps --install-codex --register-codex --dry-run
```

Просмотрите план. Для выполнения:

```bash
sh install.sh --install-apps --install-codex --register-codex
```

На AAF-Note GIMP 3.2.8 через пользовательский Flatpak, Blender 3.4.1 и Codex
уже установлены. Для нового checkout достаточно:

```bash
sh install.sh --register-codex --mcp-name creative-mcp-portable
```

Имя отличается намеренно: ранее зарегистрированный `creative-mcp` указывает на
`~/git/creative-mcp`. Этот репозиторий не перезаписывает тот проект и его MCP.
После переноса графического адаптера можно самостоятельно выбрать основное
подключение и удалить ненужную регистрацию через `codex mcp remove NAME`.

## Быстрый старт: Windows PowerShell

Заранее установите Python 3.11+ и Git. Для автоматической установки Codex нужен
Node.js LTS (npm). После установки откройте новый терминал.

```powershell
git clone https://github.com/AlekseyAnoshko/mcp_for_photos_videos.git
cd mcp_for_photos_videos
py -3 scripts/deploy.py --install-apps --install-codex --register-codex --dry-run
py -3 scripts/deploy.py --install-apps --install-codex --register-codex
```

Также предусмотрен `install.ps1` с теми же аргументами. Прямой запуск Python
позволяет не менять PowerShell ExecutionPolicy ради установщика.
Если приложение поставлено в нестандартную папку, задайте команду явно.

## Настройки и повторный запуск

| Параметр | Назначение |
|---|---|
| `--install-apps` | Установить только не найденные совместимые GIMP / Blender |
| `--install-codex` | Установить Codex, если он не найден; вход остаётся ручным |
| `--register-codex` | Зарегистрировать MCP с абсолютными путями |
| `--mcp-name NAME` | Имя подключения, по умолчанию `creative-mcp` |
| `--workspace PATH` | Папка материалов новой конфигурации, по умолчанию `~/CreativeProjects` |
| `--config PATH` | Отдельная конфигурация; подходит для нескольких установок |
| `--gimp-command JSON` | JSON-массив команды GIMP вместо автообнаружения |
| `--blender-command JSON` | JSON-массив команды Blender |
| `--dry-run` | Только обнаружение и печать плана; без записей и установок |
| `--doctor` | Только чтение конфигурации и проверка версий |

По умолчанию настройки хранятся в `~/.config/creative-mcp/config.json`
(`XDG_CONFIG_HOME` учитывается), на Windows — в `%APPDATA%/creative-mcp/config.json`.
Сервер также понимает переменную `CREATIVE_MCP_CONFIG`; установщик передаёт её
при регистрации Codex.

Существующая конфигурация **не перезаписывается**. Если требуется изменить команды
или папку материалов, отредактируйте JSON вручную либо выберите новый `--config`.
В `config.example.json` приведён пример для Linux Flatpak.

Пример явно заданной команды:

```bash
sh install.sh --config "$HOME/.config/creative-mcp/custom.json" \
  --gimp-command '["/usr/bin/flatpak", "run", "--user", "org.gimp.GIMP"]' \
  --blender-command '["/usr/bin/blender"]'
```

Установщик распознаёт native GIMP 3 и пользовательский/системный Flatpak,
типичные приложения `/Applications` на macOS, Program Files и LocalAppData на Windows.
Произвольные portable-папки задаются через параметры. Старый GIMP 2.10 не выбирается
для адаптера. Папка материалов — договорённость для будущих адаптеров, **не sandbox**
всего процесса: базовый сервер пока не имеет инструментов редактирования файлов.

## Подключение и минимальная проверка

Запустите новую сессию `codex`, войдите через **Sign in with ChatGPT**, если требуется.
Попросите: «Вызови system_info через creative-mcp» (или имя из `--mcp-name`).
Это единственная обязательная проверка после развёртывания.

Если нужна диагностика без запуска Codex:

```bash
sh install.sh --doctor
```

Не запускайте `creative-mcp` вручную для визуальной проверки: STDIO-сервер ждёт
MCP-клиента, а не ввод обычного терминала. Веб-сервера, systemd-службы, Docker,
nginx, входящих портов и отключения sandbox Codex для обычной работы не требуется.
Установку пакетов можно выполнять из обычного терминала, если сеть sandbox недоступна.

## Версии и обновления

SDK зафиксирован как `mcp==1.26.0`. Транзитивные зависимости выбирает pip;
после установки их точный снимок записывается рядом с конфигурацией в
`requirements.resolved.txt`. Это **локальный снимок**, а не универсальный lock-файл
для всех ОС. Сборки GIMP/Blender/Codex при первой установке берутся из текущих
официальных каналов/пакетных каталогов, поэтому развёртывание не побитово одинаково.

Повторный запуск переиспользует `.venv`, оставляет существующие настройки и не
обновляет уже найденные приложения. Для обновления кода выполните `git pull --ff-only`
и повторите установку без `--install-apps` / `--install-codex`, затем перезапустите Codex.
При смене Python, ОС или перемещении checkout создайте окружение заново и скорректируйте
регистрацию MCP. Не переносите `.venv` между компьютерами.

Установщик не выполняет автоматический rollback пакетного менеджера. При сбое
уже установленные компоненты остаются; устраните указанную причину и повторите запуск.

## Удаление

1. Удалите только нужную регистрацию: `codex mcp remove creative-mcp` (или своё имя).
2. Удалите `.venv` и checkout, если они больше не нужны.
3. По желанию удалите отдельную конфигурацию и снимок зависимостей.

Материалы в `~/CreativeProjects` и приложения GIMP/Blender остаются.
Не удаляйте общие программы и Flatpak runtime, которыми пользуются другие проекты.

## Развитие

1. Перенести проверенный GIMP 3 batch-адаптер: XCF, слои, маски, PNG/WebP.
2. Добавить Blender-адаптер: сцены, титры, камеры, анимация и рендер.
3. Общие операции: сохранение новых версий, устойчивые ID объектов, пакет правок
   за один запуск, предпросмотр, отмена долгих заданий, ограничение путей.
4. Затем при необходимости — шаблоны заставок, удалённый GPU и локальная веб-панель.

Новые адаптеры должны работать внутри своего приложения: Python/GObject GIMP
внутри GIMP, `bpy` внутри Blender. Не устанавливайте их в `.venv` MCP.
Фотографии, XCF, BLEND и видео не входят в исходный репозиторий.

## Проверки разработки

```bash
python3 -m unittest discover -s tests -v
```

Небольшие тесты проверяют выбор пакетных команд, сохранение конфигурации и регистрацию
MCP; они не устанавливают программы. Реальные GUI/Flatpak/UAC-проверки выполняются
на целевой машине, а не объявляются успешными по результатам mock-тестов.

При подготовке версии 0.2 выполнены: 9 unit-тестов, проверка синтаксиса `install.sh`,
установка пакета в чистое venv с SDK 1.26.0 и реальный обмен STDIO
initialize → list_tools → system_info. В последней проверке команды GIMP/Blender
заменялись управляемыми заглушками; графические программы на машине сборки не запускались.
SDK с текущим pydantic-settings выдаёт `IncompleteFieldDefinitionWarning` для
`lifespan`; проверенный обмен MCP от этого не прерывается. Предупреждение не скрывается.

`scripts/smoke.py` можно запускать Python-интерпретатором установленного `.venv`
вместо проверки через Codex; он читает ту же конфигурацию, включая
`CREATIVE_MCP_CONFIG`, и требует доступности обоих приложений.
